# Windows native workbench and feasibility probe

An isolated v0.6.0 development application. It does not replace the current PortCanvas application. macOS adaptation is outside the current scope.

The window uses Slint/winit/FemtoVG and native OpenGL. The terminal uses `alacritty_terminal`; RFB uses `vnc-rs` over an owned loopback fixture; H.264 decoding and test-video generation use Windows Media Foundation. Native signature verification accepts the existing signer's format and requires its authenticated version field. There is no Tauri, WebView, noVNC or xterm dependency in this crate's active Windows build graph.

The crate now links [the shared business services](../core/README.md). With `WCS_TEST_ROOT` set, `PortCanvasNativeProbe.exe --core-smoke` constructs, reads and shuts down those services in an isolated data directory without opening a window or connecting a device. The graphical prototype uses isolated development data. SSH, tmux, SFTP and x11vnc have also been checked against the reference Ubuntu 20.04 ARM64 controller; the complete hardware/performance acceptance remains outstanding.

## Native application

`PortCanvasNative.exe` is the default GUI binary. It provides saved device profiles, password/private-key SSH authentication, host identity confirmation, connection progress/cancellation/disconnect, explicit LAN discovery, local log browsing/cleanup, language, appearance/accent palette, desktop quality and runtime-source preferences, and the local log-size limit. Both the legacy and native adapters use `core::application` for profile actions and SSH trust policy. Connection details and errors come from the shared services; switching pages or appearance does not reconnect the device.

The current workbench is a functional development UI. The final native interface will use v0.5.95's layout, navigation, interactions and visual style as its reference after the functional chain is integrated; effects still require performance validation.

The default development data directory is `%LOCALAPPDATA%/PortCanvas/NativeDevelopment`. Set an absolute `WCS_DATA_DIR` to use isolated fixtures. It does not automatically import production profiles or migrate data. Saved credentials use the shared Windows protection mechanism. The window does not scan the LAN automatically; discovery starts only when Search is pressed. Do not point the development build at the sole copy of production data.

The terminal page now uses the shared PTY/tmux pool and local log observer. Tabs keep independent VT grids, selections, command drafts, command history and log projects. Connect/resume and detach preserve the remote session; restarting or closing requires confirmation and uses the shared lifecycle. Direct input uses native committed text and IME preedit at the VT cursor. Ctrl+Shift+C copies the selection, Ctrl+V pastes, and Ctrl+Tab moves focus from remote input to the log-project field. Raw Tab goes to the PTY. Connection readiness requires PTY/exec acceptance and the first stdout screen from tmux, so input is not enabled during its initial attach. For isolated real-device checks, `WCS_TERMINAL_NAMESPACE` selects a separate terminal namespace without changing the profile or production sessions.

The command editor supports IME, selection/caret editing, expanded mode and up to 100 successfully submitted commands per tab in memory. In collapsed mode, Enter sends, Shift+Enter inserts a newline, and Up/Down browse history for a single-line draft, restoring the unsent draft when moving past the newest entry. Expanded mode uses Enter for newlines; Ctrl+Enter sends in either mode. Failed sends retain the draft.

Tab requests command/path candidates through the existing shared SSH completion service without writing to the PTY. The current shell word is replaced with quoted text, preserving the rest of the draft and UTF-8 selection-start offsets. Multiple matches can extend a common prefix; a truncated result does not. Up/Down or Tab/Shift+Tab select, Enter or a pointer chooses, and Escape cancels before exiting full screen. The candidate viewport shows four rows and scrolls to the keyboard selection. Editing, changing the completion position, losing focus, changing tabs/pages or hiding the window invalidates pending results. Requests are bound to the terminal ID and local request serial. No shell evaluation is performed by the native word scanner.

Output uses the shared 256-KiB-per-stream credit window, acknowledged after parsing, with coalesced UI wakes and 1,000 lines of scrollback. Only the visible, non-minimized terminal grid is rendered. Hidden tabs continue parsing and recording; wheel scrolling changes local history without sending mouse/arrow reports. PTY resizes are coalesced for 80 ms. The shared connection generation and terminal stream IDs reject stale input/output; queued final output can still be displayed after a terminal exits.

The log page uses the shared 200-record cursor pages and 256-KiB detail tail, with project/day/status filters, a virtualized list, read-only original output, completeness notices, selectable finished records and confirmed cleanup. Root changes preserve the previous files and invalidate old view requests. Only the selected running record is polled, and polling stops off-page, while minimized/occluded or during confirmation. Completed task handles are reaped as new log work starts. Opening the log root creates that directory if necessary; opening a selected record requires its directory to exist.

Blue/green/graphite accent palettes apply to navigation, selection and primary actions; other standard widgets retain their platform styling. F11 and the toolbar toggle full screen, and Escape exits it when no confirmation is open. Those application shortcuts are consumed before remote input. The Arena and background-media flows are integrated. Full DPI/accessibility coverage, the remaining window interactions, final visual materials and feature parity are still outstanding. The separate `PortCanvasNativeProbe.exe` remains available for controlled renderer/codec/input experiments.

For local SSH GUI checks, `cargo build --locked --example workbench_fixture` builds an owned loopback server. With an isolated `WCS_TEST_ROOT`, it writes `fixture-ready.json` containing its ephemeral port and data directory. Launch the application with `WCS_DATA_DIR` set to that directory. The fixture accepts only synthetic credentials, executes no commands, and exits after ten minutes or when `fixture-stop` appears. Its final report contains the successful authentication count. No private key is written to disk.

`cargo build --locked --example logs_fixture` creates a separate local log fixture. It requires a fresh isolated `WCS_TEST_ROOT`, generates 208 records (including a live external writer, failed/interrupted records and long Unicode output), and writes its development data location to `logs-ready.json`. It executes no commands and exits after fifteen minutes or when `logs-stop` appears. The optional `PORTCANVAS_WORKBENCH_REPORT` contains page/detail-read counters and visibility observations for local lifecycle checks; it does not contain log text or credentials.

`cargo build --locked --example terminal_fixture` builds a loopback SSH protocol fixture for the terminal UI. A fresh isolated `WCS_TEST_ROOT` receives `terminal-ready.json` (data directory, ephemeral port and public fingerprint). It uses synthetic credentials, emulates environment/bootstrap/control/completion replies and echoes PTY bytes; it never invokes a shell or tmux. `fixture-lines` requests 1,400 synthetic lines and `fixture-modes` enables application-cursor/bracketed-paste/mouse modes. Completion fixtures include `py`, `中`, `single`, `many` (64 truncated matches) and `slow` (three-second reply). It exits after fifteen minutes or `terminal-stop`. Reports contain sizes, byte/query counts and owned-channel/session counters, not input payloads. This fixture tests the native/shared-service wiring, not a real tmux server or controller.

The remote desktop page now shares the existing environment/bootstrap and authenticated SSH connection, but supplies an in-process direct-tcpip stream to native RFB decoding and Slint rendering. It opens no native HTTP/WebSocket listener. Smooth/clear/economy preserve the shared tuning, with Tight quality/compression negotiated before the initial update. Local fit/original-size controls never request physical X11 display changes. Input is gated by a complete framebuffer update and an AfterRendering notification; this is not a physical-display or latency measurement.

Pointer buttons, drag, bounded wheel pulses, keyboard modifiers, Unicode/IME text and server cursor metadata use bounded/coalesced channels. Ctrl+Tab returns focus to the local toolbar. Read-only, focus loss and cancellation release tracked keys/buttons. Leaving the page or hiding/minimizing the window stops decoding and closes the owned desktop process/tunnel; returning resumes only a previously requested desktop. Closing the desktop leaves the parent SSH connection available. Standard RFB clipboard text is Latin-1: transfer is explicit in each direction; other characters can be entered through the native text path. There is no automatic system clipboard synchronization or UTF-8 clipboard extension.

`cargo build --locked --example desktop_fixture` builds the owned loopback SSH/RFB fixture. Use a fresh isolated `WCS_TEST_ROOT`; `desktop-ready.json` records the data directory, ephemeral port and public fingerprint. It emits only synthetic gradient/cursor/pointer feedback, changes its synthetic framebuffer on F2 and echoes clipboard messages. It never invokes a shell, x11vnc or a hardware display. It exits after thirty minutes or `desktop-stop`; reports contain counts and negotiated metadata, not input or clipboard contents. Integration tests also exercise absent/partial first frames, extra authentication rejection, stale connection/frame generations and channel/input cleanup. The reference controller has supplied a complete real x11vnc frame and native GUI rendering; full key/IME/platform coverage and performance gates remain outstanding.

## Build and test

The Files page uses the shared local/SFTP service for dual-pane browsing, paths/home/parent, a native local-folder picker, checkbox or Ctrl/Shift row selection, double-click/Enter directory navigation, folder creation, recursive upload/download, rate limits and cancellation. Overwrites and remote deletion require the native confirmation surface. File names and paths remain untranslated. Read results belong to a pane request and device generation; native mutations carry the selected remote generation into the shared service. A device replacement cannot redirect queued writes to its SFTP connection. The old adapter remains compatible with requests that omit the optional generation field.

Lists are virtualized, changed rows are updated in place, and file-state wakes are coalesced. No directory polling runs while idle or hidden. Transfers continue when changing pages or minimizing; returning refreshes a directory changed by a completed operation. The shared 64-KiB transfer buffer, exclusive temporary files, source/target validation and atomic-publication policy remain in force. Cancellation preserves completed files; it is not a batch rollback.

`cargo build --locked --example files_fixture` provides an owned loopback SSH/SFTP peer mapped only to a fresh `WCS_TEST_ROOT/remote-files`. It creates synthetic local/remote data and writes `files-ready.json` containing the public host fingerprint and isolated application directory. The GUI uses `WCS_TEST_ROOT/local-files` when the test root is absolute; normal development runs still start in Documents. The fixture never invokes a shell or a device and expires after one hour or `files-stop`. Its replace-extension emulation verifies wire dispatch and content on disposable files, not the atomicity of a real OpenSSH server.

The Files page also accepts native Windows file/folder drops and pane-to-pane drags into the current directory or a directory row. Dragging a selected item preserves the selection; dragging an unselected item transfers that item. Escape, focus loss, hidden pages and device replacement clear pending gestures. Both paths reuse the same overwrite, cancellation and temporary-file publication service. The local drive selector uses the shared Windows drive inventory; explicit paths and the folder picker remain available. List geometry is synchronized to native input in logical coordinates, including scrolling. Full keyboard/DPI/accessibility coverage and transfer/performance acceptance across devices remain migration work. The UI remains the development workbench described above.

Windows x64, Rust 1.90+, the MSVC build environment and Windows system media codecs are required. From this directory in Git Bash:

```bash
mkdir -p target/local-tests
export WCS_TEST_ROOT="$(cygpath -w "$PWD/target/local-tests")"
cargo test --locked
cargo build --locked --features gui --release
target/release/PortCanvasNative.exe
```

To generate a disposable, silent 320×180 H.264 fixture and run the window:

```bash
target/release/PortCanvasNativeProbe.exe --media-fixture "$WCS_TEST_ROOT/synthetic.mp4"
export PORTCANVAS_PROBE_VIDEO="$WCS_TEST_ROOT/synthetic.mp4"
export PORTCANVAS_PROBE_REPORT="$WCS_TEST_ROOT/gui-report.json"
target/release/PortCanvasNativeProbe.exe
```

The fixture destination must not exist. The report is optional and contains local terminal text, delivered frame counts, native-hide observations and worker errors. Use synthetic text rather than secrets. The window echoes local input and never executes shell commands. Its desktop button connects only to a generated loopback server. Tab changes, native minimization/occlusion, stop and exit cancel owned workers; exit joins them. Images pass through bounded latest-frame slots. The render timer runs only while a stream is active. The native media probe uses RGB32 CPU decoding/conversion and GPU texture upload; it does not yet establish hardware-decoder or zero-copy behavior.

## Acceptance boundary

The separate M1 probe tests VT parsing/scrollback/selection, a synthetic RFB client/server path, system H.264 video and signed-version checks. The workbench adds locally verified direct IME composition, Unicode input, selection/clipboard, two SSH PTYs, command drafts, resize and shared lifecycle tests. All terminal modes/modified keys, queue saturation, screen-reader coverage, remaining tmux/x11vnc modes and long-running cases, real-device latency, production clipboard behavior, broader codec/large-media coverage, final background compositing and the installer/update migration remain outstanding. Local loopback SSH/GUI checks do not establish real-controller compatibility or a performance result.

Slint 1.16.1 showed repeated missing-CJK-segmentation diagnostics in the tested Windows text path. This probe pins 1.15.1, whose text and controls were checked locally. This is a prototype choice, not a frozen final GUI decision; egui/eframe remains an alternative to compare when the remaining gates can be measured.

The public test vectors in `tests/fixtures/update.json` were produced with the existing Tauri CLI signer using disposable keys. They contain no private key. That legacy comparison tool is not part of this native crate's build or runtime. Signature compatibility does not prove cross-stack installer compatibility. Nothing in the probe downloads or executes updates.

## Native arena

The Arena page draws the existing 3.8 m square coordinate system and platform asset natively, with the origin at the lower left. It overlays only accepted, current pose samples from the shared read-only pose service. Missing, invalid, expired and tracking-lost data hide the point and coordinates. The UI also expires a previously valid sample if fresh packets stop arriving. No localization algorithm or simulated production position is supplied.

Device metrics use the shared SSH sampler every two seconds while the page is visible and connected. CPU/network rates require compatible monotonic samples; missing readings stay unknown. Separate CPU/memory plots retain at most sixty seconds and break across errors. Visible numerical readings accompany the plots. Camera controls and metrics use a bounded, scrollable side pane.

Camera preview is explicitly enabled, with the existing 8/15/20/30 FPS choices. The native path reuses the SSH capture helper, component preparation, heartbeat and owned-process cleanup; it exposes one latest JPEG directly to the native decoder and creates no local HTTP preview listener. Decoded RGB frames use a latest-frame slot and texture updates only while a camera is active. JPEG dimensions are checked before allocation. The legacy adapter retains its HTTP MJPEG path.

Leaving the page, hiding/minimizing, changing the connection or exiting cancels camera/pose ownership and stops metrics polling. Restoring the page restarts metrics/pose but leaves the camera off. Native starts carry the expected SSH generation and cancellation token across lifecycle locks, so stale starts cannot replace a newer connection's capture. Camera-stop does not disconnect SSH.

`arena_fixture` is an owned SSH peer with synthetic metrics, a generated JPEG and explicit synthetic pose states; it opens no device and runs no supplied commands. A fresh `WCS_TEST_ROOT` receives `arena-ready.json`, `arena-counts.json` and the isolated application data. `arena-pose-mode` selects missing (0), valid (1), stale (2), invalid (3) or tracking lost (4). It expires after thirty minutes or `arena-stop`.

`real_arena` requires an isolated trusted `WCS_TEST_ROOT/data/devices.json`. It checks real metrics and uses a unique RAM file for clearly synthetic pose protocol samples, removing that file afterward. Set `PORTCANVAS_REAL_CAMERA=1` only when the attached camera may be opened for this check. The reference controller delivered 640×480 native JPEG and the Windows GUI was checked at 125%, including actual device release on minimize/leave and camera-off on restore. These checks do not establish localization accuracy, arbitrary cameras, the full DPI/accessibility matrix or a performance/latency comparison.

## Explicit real-device acceptance

`cargo build --locked --example real_connection` builds a manually invoked acceptance runner. It requires an absolute `WCS_TEST_ROOT` containing `data/devices.json`, copied from an already trusted profile with saved credentials. It rejects unknown host identities and never prints plaintext secrets. Keep this root separate from production data and close other test clients that share it. The runner creates a uniquely named temporary remote directory and terminal namespace, verifies recursive Unicode SFTP/overwrite cancellation/transfer interruption, actual PTY size and same-shell detach/SSH reconnect, and a complete native RFB frame. It then removes its directory/session and shuts down the connection. Results are written to `real-connection-result.json`; no hardware program or update is run. This is an opt-in real-device check, not a CI fixture or a resource/latency benchmark.

## Native background media

Settings supports a six-digit hex color, PNG/JPEG/WebP images, and MP4/WebM video through the installed Windows Media Foundation codecs. Imported media is streamed to a managed local draft without a file-size cap. Decoded images and video frames retain a 128-MiB pixel budget; images are resized for native texture display. The original selected file is preserved. A crop is stored in the existing normalized configuration format: drag inside to move, drag a corner to resize, or use arrows and Shift+arrows. Enter applies and Escape cancels. Cancelled or failed imports preserve the previous background and remove their draft.

The saved video and settings preview share the same native texture. Only a separate muted crop preview is decoded while editing; the saved video pauses during editing/import and the native file picker. Playback retains one latest frame and uses timestamp/sample-duration pacing, with an audio presentation clock when sound is active. Audio uses a separate audio-only system topology and per-session volume; it never changes the system master volume. The default volume is zero and creates no audio output. Muting releases that output. Audio failures keep video running silently and display a brief notice.

Minimizing/occluding pauses decoding, audio and texture updates; restoring resumes playback. Apply/replacement closes media readers before renaming or removing managed files. Closing joins owned workers and releases their files. There is no native media HTTP listener or browser player, and no playback thread or repeating media timer for the default/color/image-only background. The development overlay currently changes opacity; the final v0.5.95 visual style and performance gate remain separate work. Video conversion is still RGB32 on CPU plus native texture upload, without a claim of hardware decoding or zero copy.

`background_fixture` creates disposable PNG/JPEG/WebP files, a damaged PNG and a generated H.264/AAC video under a fresh `WCS_TEST_ROOT`; it does not start a server. `background_acceptance` uses an actual audio output to check native playback, two loops, per-session volume, pause stability, mute release and natural-end restart. An optional `PORTCANVAS_WEBM_FIXTURE` adds a local WebM decoder/audio check. This opt-in example is distinct from the silent automated tests. `PORTCANVAS_WORKBENCH_REPORT` additionally records background frame/upload counts and hide/restore observations without media paths or content.
