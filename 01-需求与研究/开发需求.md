# 开发需求

日期：2026-10-21；状态：需求基线草案。

| 编号 | 功能 | 结果要求 |
| --- | --- | --- |
| S01 | 连接管理 | 统一填写设备地址和账户，显示各功能实际连接状态 |
| S02 | 完整远程桌面 | 显示板端现有 Linux 桌面，支持鼠标、键盘、窗口操作和尺寸适配 |
| S03 | 摄像头预览 | 显示当前选中摄像头，区分断流与新画面；已有采集源只读分流，不重复抢占设备 |
| S04 | 控制台 | 展示板端程序输出；执行命令与纯日志显示分别标明 |
| S05 | 赛台场景 | 按左 1/3、右 2/3 的布局显示自身位置/朝向、能量块、敌车及其方向；未知状态可见 |
| S06 | 文件传输 | 通过 SFTP 浏览、上传、下载，显示目标路径、进度和失败信息；覆盖既有文件前明确确认 |

## 性能与数据要求

- 完整桌面、视频、场景数据、日志和文件传输分别管理生命周期；隐藏页面的显示流可暂停。
- 视频与场景采用有限队列，避免积压旧结果；显示时间信息，不能用插值动画伪装新观测。
- 赛台图在电脑渲染，板端发送场景数据；监测发送与编码对车载识别的额外负载。
- 大文件传输支持限速或暂停，以对照验证对实时通道的影响。
- 比较软件与 NoMachine 时固定网络、分辨率、画质和车载任务，分别记录连接耗时、输入到显示延迟、视频帧龄、P50/P95、资源占用和掉帧。
- 网络往返、视频帧龄与车载识别耗时分别计量；跨机器时间比较需先说明时钟同步或测量方法。
- “更轻量、更低延迟”是待验证目标，不能把软件包体积当作板端负载或响应速度。
- 只保存完成连接所需的信息，认证材料不进入仓库或普通日志。

## 视觉显示条件

世界坐标来自视觉工程。只有相对方位时显示相对标记；缺少定位、尺度或朝向时明确标为未知，不强行生成赛台绝对位置。二维投影与三维模型使用同一坐标、单位、对象 ID 和观测时间。
