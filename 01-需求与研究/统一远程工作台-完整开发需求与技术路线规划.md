## 1. 产品愿景与边界

### 1.1 产品定位

建设一款**Windows 优先、轻量化、模块化、支持第三方扩展的远程设备工作台**，将通常分散在以下软件里的体验整合到同一应用：

- 类 NoMachine 的完整远程桌面访问与操作。
- 类 WinSCP 的 SSH/SFTP 文件浏览和传输。
- 类 FinalShell 的 SSH 终端、运行状态和日志查看。
- 可选的 AI 工作区：用户自带第三方模型 API（BYOK），在授权后使用软件内部日志、设备、文件和插件数据辅助开发。
- 可安装、可关闭的场景模块/插件：轮式竞赛赛台作为**第一个官方模块**，未来允许用户根据自己的行业或项目扩展工作区。

**产品主线 A**：统一工作区、多协议集成、低门槛使用。  
**技术增强 B**：独立研究低延迟视频、连接诊断、流量控制、故障恢复和局域网/安全远程连接；不以重写 NoMachine 或自创完整网络协议为前提。

### 1.2 设计原则

- **轻量化优先**：基础程序尽量减少进程、空闲 CPU、内存和不必要的常驻资源；AI、视频、插件按需加载。
- **核心恒可用**：不开 AI、不装插件、没有公网时，受支持环境下的 SSH、SFTP、桌面、日志仍可使用。
- **竞赛先实用，未来可通用**：竞赛需求作为真实验收场景，但不能把树莓派/赛台字段写进所有通用服务接口。
- **基础能力由宿主管理**：设备身份、SSH 主机密钥、凭据、文件安全、会话和日志均属于可信核心；插件和 AI 不直接取得底层对象。
- **模块化不等于插件已开放**：内部可选模块先落地，再建设安全的第三方插件 SDK 和宿主。
- **性能以实测为准**：不能因为使用 Tauri/Rust、WebRTC 或 QUIC 就声称更快、更省资源或更稳定。
- **安全边界优先**：不自动开放公网端口，不自动执行危险指令，不让软件退出/网络中断影响车辆自主运行。

### 1.3 目标用户与初期支持范围

| 用户 | 典型场景 | 支持策略 |
| --- | --- | --- |
| 轮式竞赛开发者 | Linux 板端、视觉调试、文件与终端、摄像头和赛台 | 首个真实应用场景、优先完成 |
| Linux / 嵌入式开发者 | SSH、SFTP、桌面、持续任务、日志 | 通用核心目标 |
| 服务器和多设备维护者 | 远程连接、状态查询、多工作区 | 通用版逐步扩展 |
| 自定义插件开发者 | 串口、ROS、服务器监控、自定义面板 | SDK 成熟后开放 |
| AI 辅助调试用户 | 自带模型 Key、分析日志、辅助诊断 | 可选 AI 工作区 |

**客户端**：首先 Windows；未来 macOS/Linux 另行评估。  
**远端**：首先已有 Linux/X11 比赛控制器；其他 Linux 桌面环境按后端兼容表逐步支持，Windows 远端和跨平台客户端不预设已经支持。  
**不做**：首轮不开发自建账号云平台、公共中继网络、插件商城、云端训练模型或自动化车辆运动控制，也不要求完整复刻第三方商业软件。

### 2.3 迁移必须正视的技术债

1. 一个全局 `DeviceSession` 承担主要 SSH 生命周期；多功能共享底层 TCP 连接，可能在拥塞/断线上相互影响。
2. `desktop.py` 绑定比赛控制器的 x11vnc 文件路径与 AArch64 库目录；不能直接承诺通用 Linux。
3. 现有 keepalive 和人工重连恢复不足以称为完整连接自治与异常恢复机制。
4. 发行版用户数据当前可能在 EXE 相邻 `data` 目录；正式安装版应使用用户可写数据目录，并设计旧数据迁移。
5. 现有界面以密码输入为主，尚无完整 SSH Key 管理/系统凭据库产品体验。
6. 标题、包名、应用 ID、`wcs` 会话名、日志 schema 与数据目录包含旧项目标识；未来更名需要**迁移或兼容层**，不能直接全局替换。
7. 旧版的 IPC、Node 流与文件句柄需要替换为明确的 Rust/Tauri 服务边界；数据流处理不能通过无限堆积前端事件实现。

## 3. 技术栈决策：Demo V0.4 优先完成底层迁移

### 3.1 目标技术栈

| 层次 | 主要方案 | 选择理由与限制 |
| --- | --- | --- |
| 桌面应用宿主 | **Tauri 2 + Windows WebView2** | 优先验证安装体积、空闲资源、启动行为；WebView2 是系统运行时，绝非零内存 |
| 核心服务 | **Rust + Tokio（候选）** | 设备、会话、传输、日志及事件管道；需要处理取消、背压、错误和异步安全 |
| 前端 | **TypeScript + 现有 HTML/CSS** | 最大程度保留页面，逐步加强类型；V0.4 不强制引入 React/Vue 等 UI 框架 |
| SSH | Rust SSH 库评估 | `russh` + `russh-sftp`、基于 libssh2 的方案在目标板实测后选择；不能预先认定全面兼容 |
| SFTP | 与 SSH 实现配套的流式客户端 | 保留传输安全、确认、取消、临时文件与限速语义 |
| 完整远程桌面 | **noVNC + 当前 x11vnc + SSH 转发** | V0.4 只迁移链路不换协议，保持同条件对照；未来 `DesktopBackend` 可替换 |
| 交互终端 | **xterm.js + SSH PTY + tmux** | 保留用户使用习惯和远端持久会话；重写 Windows 端绑定与 IPC |
| 本地日志 | **Rust 服务 + 兼容现有文件格式** | 保留自动采集、状态、离线日志、项目/日期分类及缺失标记 |
| 摄像头与遥测 | `VideoSource` / `TelemetrySource` 抽象 | V0.4 预留边界，V0.5 后实现；媒体协议基于实测再决定 |
| AI | BYOK + Provider Adapter + Tool Gateway | V0.8 起逐步开发；不随基础应用常驻推理模型 |
| 插件 | 内部模块 → SDK → 受限宿主 | 初期只做可信官方模块；第三方执行须具备权限/隔离机制 |

**关于 Tauri 权限的准确理解**：Tauri 的 capabilities/permissions 可限制 WebView 调用 Rust 命令；**不意味着随意运行的 Rust 插件或第三方原生动态库已经被沙箱隔离**。开放不可信第三方插件前，必须另设计执行隔离、数据范围、审计和用户审批。

### 3.2 迁移原则与不可妥协的功能等价

- 新版基础 SSH、SFTP、完整桌面、持久终端、运行日志在 **Rust / 受控原生实现**中工作；Windows 交付的上述核心链路**不再依赖 Electron 或常驻 Node.js 辅助进程**。仅用于测试/过渡的桥接不得伪装为最终迁移完成。
- 优先复用现有页面、noVNC、xterm.js、远端 Python 启动器及 Bash/tmux 协议；不在一次迁移中并行重写全部协议与界面。
- 旧版必须保留为可执行、可比较、可回退的基线。
- 用户已有设备档案、受信主机指纹、运行日志、tmux 会话名与运行记录 ID，应保持兼容或者提供经验证的可逆迁移。**不能因迁移自动重新信任主机密钥或静默丢失历史数据。**
- Windows 普通用户权限下能够运行、保存配置和日志；安装版与便携版路径明确区分，不随工作目录变化误写数据。
- 迁移后的 SSH 密码不得出现在日志/配置/崩溃报告中，首次连接仍校验指纹；任意文件覆盖、危险操作维持确认机制。
- 不把新版本的原型空壳内存当成等价全功能产品的内存性能。

### 3.3 迁移过程中保留的远端前置条件

Demo V0.4 的兼容目标是**当前真实控制器**，而不是所有 Linux：支持现有 Linux/X11 会话、授权安装的 x11vnc 组件、Python3、Bash、tmux、base64 等；Git 用于日志项目自动识别，缺少时可回退到当前目录。不要以迁移为借口升级操作系统、替换厂商 SDK 或重新安装车载视觉环境。

**约束**：只允许一个授权采集入口拥有摄像头，预览作为订阅者，不重复打开/抢占视觉任务设备；场景 JSON 不承载完整视频帧；缺少世界坐标不将相对检测强行换算成绝对位置。消息格式以独立视觉项目确认后的权威接口为准。

### 4.3 连接可靠性和低延迟（N）

| ID | 需求 | 完成定义 | 优先级 |
| --- | --- | --- | --- |
| N01 | 通道状态分离 | 任一显示或订阅通道关闭，不自动结束别的业务；底层连接断开时各自进入正确降级状态 | P1 |
| N02 | 传输干扰控制 | SFTP 限速/可选暂停；对照验证大文件传输对终端、桌面、视频帧龄的影响 | P1 |
| N03 | 连接诊断 | RTT、状态事件、吞吐、错误类型；视频有条件时测帧龄、抖动、掉帧与缓冲 | P1 |
| N04 | 断线恢复 | 可取消的指数退避重连、身份复验、旧任务失效；不自动重复有副作用的命令 | P1 |
| N05 | 视频实时策略 | 有界队列、丢弃过时帧、真实观测时间、负载可控、页面隐藏可停止订阅 | P1 |
| N06 | 网络路径策略 | 局域网优先直连；变化时提示及可回退；TCP/SSH 并发隔离按基准结果决定 | P2 |
| N07 | 安全远程连接 | 优先借助已有 VPN/WireGuard 类组网；不默认公开 SSH/VNC；可观测才显示直连/中继 | P2 |
| N08 | 媒体/协议实验 | WebRTC/RTP 等作为独立可切换后端；QUIC 仅按需求评估；失败时回退稳定方案 | P2 |
| N09 | 公平的性能对照 | 记录固定环境中的连接耗时、输入到显示延迟、帧龄、P50/P95、CPU、内存、掉帧 | P1 |

### 4.4 第三方插件平台（PEX）

**三种层次**：① Core：可信核心，不可卸载；② Built-in Module：官方可选模块，先以源码内模块实现；③ Third-party Extension：通过限定能力的 API、独立执行环境和权限审批接入。三者不能混为一谈。

| ID | 需求 | 完成定义 | 阶段 |
| --- | --- | --- | --- |
| PEX01 | 核心/模块解耦 | 禁用 `official.arena` 后，设备/SSH/SFTP/桌面/日志仍正常 | V0.6～V0.8 |
| PEX02 | UI 扩展点 | 插件声明侧栏、工作区面板、设备卡片和命令入口，由宿主管理挂载/销毁 | V0.8～Beta |
| PEX03 | 插件 Manifest | 声明 ID、版本、API 兼容、入口、贡献点、权限、签名/来源信息 | V0.8～Beta |
| PEX04 | 公共 SDK | 类型、安全接口、事件与生命周期，示例 `activate/deactivate`；不暴露原始句柄 | Beta |
| PEX05 | 权限网关 | 读取设备、订阅视频/遥测、查看受限文件、执行操作分权限、分设备和路径授权 | Beta 必达 |
| PEX06 | 第三方隔离 | 插件 UI/逻辑与核心隔离；异常、资源滥用不会轻易阻塞核心；建立威胁模型 | 对外开放前必达 |
| PEX07 | 安装与启停 | 安装、启用、禁用、升级、卸载、兼容检查、订阅清理及故障提示 | Beta |
| PEX08 | 受控事件订阅 | 设备/日志/遥测/视频元数据带来源、时间、序号，有背压、限频、订阅上限 | V0.8～Beta |
| PEX09 | 插件数据存储 | 按 ID 隔离数据空间/配额/版本迁移，卸载数据保留需用户选择 | Beta |
| PEX10 | 开发者支持 | 示例插件、模板、模拟数据、SDK 文档、兼容性测试工具 | Beta～V1.0 |
| PEX11 | 分发体系 | 初期本地可信包；插件商店、社区审核、更新签名属于后续独立规划 | V1.0 后 |
| PEX12 | 可选远端 Agent | 需要板端专有能力时单独声明组件/版本/权限与撤销方式，不擅自安装 | 后续 |

**插件安全红线**：插件不能直接读取 SSH 私钥、API Key、OS 任意文件，也不能取得原始 Rust 会话对象、直接注册无限权命令或自行绕过审批。Tauri 自带插件机制与**用户可安装的第三方插件运行平台不是同一件事**。如果未能有效隔离任意第三方代码，则 V1.0 仅发布官方受信模块及受限声明式扩展，不能宣称已安全开放任意插件。

### 4.5 AI 工作区（AIX）

**定位**：AI 是主程序可选能力。支持用户自带 DeepSeek、OpenAI 及其他兼容 API，或未来的本地模型服务；不默认下载、加载、运行本地大模型。普通聊天与能调用工具的工作模式必须区分。

| ID | 需求 | 完成定义 | 阶段 |
| --- | --- | --- | --- |
| AIX01 | 内置 AI 工作区 | 对话、模型切换、上下文来源与调用状态；关闭 AI 不影响通用核心 | V0.8 |
| AIX02 | 模型适配 | 自定义 API Base URL、协议类型、模型 ID；先做兼容适配器并实测具体提供商 | V0.8 |
| AIX03 | 密钥安全 | API Key 存储于 Windows 受系统用户保护的安全存储，UI 只显示掩码、不写日志/导出 | 首版必达 |
| AIX04 | 上下文选择 | 用户主动选择某设备、指定日志、终端片段、选定文件及诊断快照；发送前预览范围/目的地 | 首版必达 |
| AIX05 | 只读工具 | 限权调用设备状态、日志列表/内容、文件夹和选定文本文件、诊断数据 | Beta |
| AIX06 | 操作型工具审批 | 远程命令、上传/覆盖/删除/配置修改逐次展示具体目标并确认；取消不执行 | 开放写操作前必达 |
| AIX07 | 上下文绑定 | AI 会话绑定设备 ID 和工作区；切换设备时不沿用错误目标 | Beta |
| AIX08 | 模型能力差异 | 流式/工具/图像/上下文长度按供应商实际能力协商，不能因为协议相似就假定全支持 | V0.8～Beta |
| AIX09 | 隐私与脱敏 | 默认不上传设备日志；展示数据出境目标/字节上限；敏感字段检测、最小必要发送 | 首版必达 |
| AIX10 | 请求控制 | 超时、取消、速率限制、重试上限及使用量提示；估算费用不得冒充精确账单 | Beta |
| AIX11 | 操作审计 | 记录模型、请求 ID、已授权上下文、工具、审批/结果；不存 Key/明文秘密 | Beta |
| AIX12 | 插件接 AI | 插件可声明受限 `ContextProvider` 和 Tools；宿主统一授权、校验、记录 | Beta / 预览 |
| AIX13 | 不可信内容防护 | 日志、文件、远端 stdout、插件文本都当成数据而非提权指令，工具操作二次校验 | 首版工具必达 |
| AIX14 | 故障隔离 | API 超时、限流、余额不足/网络错误不影响 SSH/SFTP/远端程序；会话可选本地保存 | 首版必达 |

**数据外发规则**：AI 读取本地日志不代表允许把日志发给第三方云服务。首次使用、切换服务商、增加数据源时应提示；实际发送需要具备明确用户选择和可查看范围。自动分析限定**当前授权记录**，不能默默遍历整个磁盘。日志脱敏不能保证识别全部秘密。

**审批红线**：AI 不应默认执行车辆运动指令、厂商 SDK 改动、批量删除、远端系统配置变更；含副作用操作必须先显示命令/路径/设备/风险并获逐次批准，命令失败或断线不自动重放。模型不接触原始 SSH 会话、API Key 或插件内部权限对象。

## 5. 目标软件架构与接口边界

### 5.1 分层结构（目标，不表示现有实现）

```text
Tauri 2 / Windows WebView2 桌面工作台（TypeScript UI）
├─ Core Workspace UI
│  ├─ 设备 / 多工作区 / 远程桌面 / SSH 终端 / SFTP / 日志 / 诊断
│  ├─ AI 工作区（可选）
│  └─ 插件视图槽位（先官方模块，后第三方）
│
├─ Rust Application Core（可信进程 / Tokio）
│  ├─ DeviceRegistry + ProfileStore + HostKeyTrust + CredentialStore
│  ├─ ConnectionManager / SessionManager / WorkspaceManager
│  ├─ TerminalService / FileTransferService / RunLogService
│  ├─ DesktopBackend Registry / VideoSource / TelemetrySource
│  ├─ Diagnostics / Configuration Migration / Audit
│  ├─ Capability Gateway（给 UI、AI、插件共用的受控服务入口）
│  └─ Tauri Commands / Events（最小权限、参数校验、受控队列）
│
├─ Protocol Adapters（可替换）
│  ├─ SSH / SFTP Rust 实现
│  ├─ VNC over SSH（当前兼容后端）
│  ├─ SSH PTY + tmux；原日志标记协议
│  └─ 未来视频 WebRTC / 遥测 / 更多桌面协议
│
├─ Optional AI Runtime
│  ├─ Provider Adapters（用户自带 API）
│  ├─ Context Gateway / Token Budget / Send Preview
│  └─ Tool Registry / Approval / Audit
│
├─ Optional Official Modules & Extension Host
│  ├─ official.arena（竞赛实时赛台）
│  ├─ official.device-monitor（可选后续模块）
│  └─ 第三方 Extension Runtime（仅安全验收完成后开放）
│
└─ Remote Systems
   ├─ 标准 SSH/SFTP 服务
   ├─ 已有图形桌面 / 按需使用的受支持桌面后端
   └─ 可选摄像头订阅、视觉遥测、轻量远端 Agent
```

### 5.2 核心服务接口（名称为建议，不是已存在 API）

| 接口 | 职责 | 不应做的事 |
| --- | --- | --- |
| `DeviceRegistry` / `ProfileStore` | 设备资料、schemaVersion、独立身份和能力配置 | 不存明文密码、不写死比赛字段 |
| `ConnectionManager` | SSH 登录、主机校验、取消、连接状态和重连 | 不拥有赛事渲染逻辑 |
| `SessionManager` | 各设备/通道代际 ID、创建关闭、过期请求拒绝 | 不因 UI 隐藏就误停远端程序 |
| `DesktopBackend` | `connect/disconnect/state/capabilities`；第一后端为 VNC over SSH | 不假设所有桌面都用 X11 |
| `FileTransferService` | SFTP 列表、任务、限速、取消、冲突检查、临时文件 | 不用失败重试覆盖他人文件 |
| `TerminalService` | PTY 数据、窗口尺寸、tmux 会话恢复 | 不因日志采集故障终止终端任务 |
| `RunLogService` | 命令标记解析、持久存储、缺失/中断标记、离线检索 | 不补造断线期间输出 |
| `VideoSource` / `TelemetrySource` | 有界订阅、数据来源、时间、背压及取消 | 不抢占板端已有视觉采集源 |
| `CapabilityGateway` | UI/AI/插件调用校验、授权与审计 | 不直接向外传私钥/原始会话对象 |
| `WorkspaceManager` | 布局、窗口、设备绑定、模块组合 | 不控制车载自主闭环 |

**线程与消息原则**：耗时网络、视频和文件读写不能阻塞 UI；大量日志、媒体帧不经由无界 Tauri 事件堆积。对于持续字节流，应选有界通道、显式背压或受控流式桥接，并定义取消、超时及生命周期。所有前端状态更新必须携带设备/会话身份，防止旧请求回流污染新设备界面。

### 5.3 数据格式和历史兼容

- 设备配置由当前 `profiles.cjs` 的设备 ID、主机、端口、用户名、display/xauthority 映射到新 schema；旧版本的主机指纹信任记录必须保留并可验证。
- 本地日志兼容既有 `wcs.run/1`、`run.json`、`output.log`、项目/日期/运行编号结构；旧数据保留可读，不必一次性全部格式升级。
- tmux 持久会话基于旧 `wcs-...` 命名规则与专用日志会话；迁移应优先恢复/检测已有会话，避免与旧会话冲突。
- 原应用名可能同时存在于安装路径、日志根目录、应用 ID 与协议标记中；未来品牌更改采用别名/迁移层，不能随意替换导致丢数据。
- 安装版优先使用用户配置/数据目录；便携版可以选择相邻数据路径，但必须明确用户授权及回退策略。
- 日志、认证配置、密钥、视频数据及测试原始证据继续遵守 `.gitignore` / 工作区规则。

### 5.4 官方赛台模块和插件契约

`official.arena` 是示范插件，但 **V0.6 的“可选官方模块”不等于已经有第三方运行时**。它应能够消费 `TelemetrySource` 数据、注册工作区视图、订阅/取消摄像头和场景消息、关闭后释放资源。

插件 Manifest **未来示意格式**，不得视为现有接口：

```json
{
  "id": "official.arena",
  "name": "轮式竞赛赛台",
  "version": "0.1.0",
  "apiVersion": "1",
  "contributes": { "views": ["arena.workspace"] },
  "permissions": ["device.status.read", "telemetry.read", "video.subscribe"]
}
```

最小插件授权工作流：**安装/检查来源 → 读取 manifest → 兼容性与权限申请 → 启动隔离宿主 → 限权订阅/显示 → 停用清理 → 记录异常**。第三方插件不能通过 JS `require`/Rust 原生动态库直接获得宿主无限权限。用户自行安装的任意代码需要专门的威胁建模、进程/系统级隔离或选择受限的声明式执行方案。

### 5.5 AI 与插件共享的工具网关

```text
用户选择当前设备 + 指定日志/文件/诊断上下文
                ↓
AI Context Gateway：权限校验、快照、脱敏提示、范围/大小限制、发送预览
                ↓
用户配置的模型 Provider（经 HTTPS；本地模型需单独配置）
                ↓
模型返回普通文本或建议 Tool Call
                ↓
Tool Registry → 设备/权限/参数/路径核验 → 必要时用户逐次审批
                ↓
复用可信的 Logs / Terminal / SFTP / Diagnostics 服务
                ↓
结果及审计返回 AI 工作区；未授权则拒绝
```

优先实现的**只读工具**：

- `devices.getStatus(deviceId)`：设备与通道状态，不暴露密码。
- `logs.listRuns(filters)` / `logs.readRun(runId, maxBytes)`：受限记录检索，含完整性和缺失标志。
- `terminal.getSessionInfo(deviceId)`：已获授权的会话状态/少量输出片段。
- `files.listDirectory(deviceId, path)` / `files.readText(deviceId, path, maxBytes)`：仅允许选择的路径范围。
- `diagnostics.getSnapshot(deviceId)`：可用指标、测量方法、时间与未知标记。

**写入类工具后做**：`terminal.execute`、`files.write/overwrite/delete`、`settings.update` 和插件自定义动作；默认拒绝，有具体设备/命令/路径/风险、用户逐次确认、结果与审计。任何工具都不能因为模型在日志里读到“请忽略安全规则”等文字就提高权限。插件贡献工具也要经过同一网关审核，不向插件转交用户 AI API Key。

## 8. 性能目标、测量方法和验证矩阵

### 8.1 轻量化测量规范（Demo V0.4 P0）

- **统一环境**：同一 Windows 电脑、Windows 版本、WebView2 版本、屏幕尺寸、设备和网络，记录 CPU/内存、后台程序、远端负载、应用版本与测试时间；多次重复，记录波动。
- **整个进程树**：测 Electron 主/渲染/辅助进程与 Tauri 主程序/WebView2 子进程的**总内存**；避免把系统 WebView 共享进程算成零成本，也不要将不相关进程重复计入。
- **同时测 CPU 和响应**：空闲资源降低不能以桌面卡顿、终端输入延迟变大为代价。
- **静态与动态区分**：冷启动、进入工作区、连接终端、桌面持续操作、SFTP 上传、并行、断开/重连、结束后资源回收分别采样。
- **关注趋势**：短时取样和持续运行期间的内存峰值、稳定态、异常增长和释放行为都要记录。
- **不拿空壳和全功能对比**；M1 原型数字只用于探索，正式结论必须 M5 同功能测量。

### 8.2 指标

| 指标 | 核心记录 | 不能混淆的概念 |
| --- | --- | --- |
| 进程树内存 | 工作集 / Private Bytes 或定义明确的同一种口径，基线/峰值/多轮测量 | 可执行文件大小不是内存占用 |
| CPU | 客户端总 CPU 与板端相关进程占用 | 不能只测前端窗口 |
| 启动 | 冷/热启动至可交互的时间点，记录方法 | 进程创建不等于已可操作 |
| SSH 连接 | 发起连接至认证就绪时间、失败和重连次数 | RTT 不等于 SSH 完整连接耗时 |
| 输入到显示 | 定义输入事件至远端效果出现的端到端方法 | SSH RTT 不是桌面输入延迟 |
| 视频帧龄 | 展示帧相对采集观测时刻的年龄 | 跨机器时钟未同步不能直接相减 |
| P50/P95 | 同一指标重复样本的中位数和 95 分位数 | 不能把极少样本当稳定分布 |
| 文件传输 | 吞吐、限速、取消耗时、错误与完整性 | 速度快不等于覆盖安全 |
| 可靠性 | 故障发现、重连耗时、意外退出、数据损坏 | 单次成功不等于长期稳定 |

## 9. 安全、隐私和车辆边界

1. **凭据**：SSH 私钥、密码、API Key 不进入仓库、普通日志、界面消息、发布包或错误上报；云模型请求由可信后端发起。密钥加密存储与 OS 用户身份绑定。
2. **主机校验**：主机公钥变更必须阻止自动重连并提示，不能因为用户保存过 IP 就自动信任新指纹。
3. **本地桥接**：noVNC/本地 WebSocket 服务仅可在必要时按会话开启、绑定环回、避免固定可猜地址，并在断开时关闭。
4. **文件安全**：路径/文件名类型校验、覆盖确认、链接处理、临时文件隔离，删除和写入应在用户授权范围内。
5. **AI 数据出站**：日志、文件内容、设备数据发送云模型前展示目的地、范围和来源，默认最小化；模型服务的隐私条款由用户自行选择服务商时确认。
6. **提示词注入**：远端文件、日志、终端输出和第三方插件内容均是不可信数据，不能要求工具执行、修改软件权限或冒充用户授权。
7. **插件隔离**：不能只依赖 Tauri capability 就认为第三方任意代码安全；启用时需要明确来源、权限边界和执行隔离。
8. **车辆安全**：宿主和 AI 均不得默认执行车辆运动指令；不允许修改厂商 SDK、擅自恢复暂停任务或影响比赛车独立运动闭环。
9. **隐私日志**：本地调试日志可能包含登录名、路径、密钥输出或用户数据；提供清理及必要时脱敏导出，不在默认诊断上传中包含原文。
10. **安全发布**：第三方依赖许可证、供应链、自动更新签名/校验、普通用户写入权限及卸载清理行为必须在公开发行前审查。

## 11. 风险和需要实验验证的决策

| 风险/问题 | 影响 | 应对方法 |
| --- | --- | --- |
| Tauri WebView2 与 noVNC/xterm 兼容差异 | 输入/渲染倒退 | M1 先做最小用例，M2 实机验证 |
| Rust SSH 算法与旧板卡差异 | 无法连接/转发/PTY | 同条件实测候选库；保留旧版作为对照 |
| 迁移数据目录或日志格式错误 | 配置/日志丢失 | 迁移前备份、幂等步骤、旧格式兼容、回滚 |
| Tauri 原型轻但完整桌面不轻 | 轻量目标失败 | M5 全进程树测量，记录真实取舍 |
| WebView 媒体通路缓冲或复制过多 | 延迟高、内存增长 | 有界队列、专属流与基准测试 |
| 共享 SSH 连接业务互扰 | 桌面/终端卡顿 | 先测限速效果，再考虑独立连接 |
| 插件执行权限过宽 | 泄露凭据/远程滥用 | 只读/最小授权、第三方隔离、延迟开放 |
| AI 发送未授权日志 | 隐私泄露 | 用户选源、发送预览、目的地显示、审计 |
| 插件与 AI 同时持有工具 | 多方权限混淆 | 统一 `CapabilityGateway`、请求身份和设备绑定 |
| 竞赛依赖渗透通用核心 | 产品通用化困难 | 官方模块独立，核心不依赖赛事 schema |
| 远端长时任务被误结束 | 实际调试受损 | tmux 生命周期验收、取消/关闭语义明确 |
| 品牌重命名破坏旧格式 | 历史日志和会话不可用 | 独立产品标识与兼容迁移，不全局替换 |

## 12. 开发路线的最终决策摘要

**近期唯一主线：**

1. 冻结 **Demo V0.3.5** 功能与性能基线。
2. **Demo V0.4** 优先完成 **Tauri 2 + Rust / Tokio + TypeScript UI** 的验证、迁移和实机/内存验收，争取在 V0.5 前完成。
3. **V0.5** 才开始摄像头实时预览，**V0.6** 才做实时赛台与独立官方模块。
4. 之后推进连接质量、通用工作区、受控插件接口和 BYOK AI 工作区；高级低延迟传输方案独立实验、可回退。
5. **开放第三方插件和 AI 写操作的时间由安全验收决定，不为版本号强行放权。**

**长期定位：**

> 一款轻量化、模块化、可由 AI 辅助操作的通用远程工作台。基础 SSH/SFTP/远程桌面/日志功能长期可靠，行业专属能力由插件提供；所有新增能力均使用可验证、可授权、可回退的方式接入。
