# Demo V0.3.5 本地运行日志

## 记录与分类

右侧终端使用专用的 `wcs-<设备账户标识>-logs` tmux 会话，保留 V0.3 原会话。首次准备时通过内存中的 Bash RC 增加命令开始、返回提示符与退出标记，不写入用户的 `.bashrc`。当前设备需要 Bash、Python3、tmux、base64 和 git（git 缺失时使用当前目录分类）。

前台命令按一次 Shell 执行记录命令、开始目录、项目、电脑端开始/结束时间、退出码及文本输出。项目默认取 Git 根目录名，否则取运行时目录名；终端栏可填写手动项目名，留空恢复自动。更改只影响后续命令，已有记录保留原分类。日期使用电脑本地日期。

独立的 tmux control-mode SSH 通道采集原始 pane 输出，不依赖前端终端栏是否展开或附着。逐命令记录之外保存“终端会话输出”，用于保留提示符、后台及交错输出；会话按项目变化分段。后台命令返回提示符时，退出码代表启动命令返回，后台 PID 单独列出，后续输出保留在会话记录。

默认位置为 Windows“文档”中的 `Wheel Combat Studio/Logs`，可在日志页更换。每个项目、日期、运行编号下有 UTF-8 `run.json` 和 `output.log`。AI 可直接读取这两个本地文件；不需要连接设备上的 Codex。界面只预览末尾 256 KiB，磁盘文件保留已采集的全部文本。

## 断线与恢复

断开终端仅关闭交互通道，设备 SSH 仍连接时日志通道继续采集。断开设备或关闭软件会封存本地记录；tmux 中的远程程序继续运行。重连读取窗口选项中仅一份最新命令状态，恢复相同运行编号，明确追加缺失标记。离线期间的输出无法补采，不将中断记录标成完整。进程异常退出遗留的 running 元数据在再次读取时转为中断。

本版不在树莓派创建日志文件；终端 Shell 的 HISTFILE 指向 `/dev/null`，命令状态只保存在少量 tmux 内存选项中。设备断电/重启会结束内存会话。嵌套 Shell、全屏交互程序的文本属于外层命令或会话记录，不推断内部子命令或将文本当成屏幕录像。

## 界面与清理

左栏顺序：设备、桌面、文件、日志、擂台。日志页离线可用，提供项目/日期/状态筛选、详情、目录打开和多选清理；窄布局改为列表和详情上下排列。日志页也可展开右侧终端。

清理前使用原生确认，默认取消；只删除选定的已结束/中断记录目录，保留活跃记录和普通用户文件。对元数据编号、受控路径及符号链接做范围检查，确认后再次核对状态。日志写入失败显示原因并停止本次记录，不结束远端程序。日志可能包含用户程序主动输出的敏感信息，清理与分享由用户选择。

## 实现依据

[tmux Control Mode](https://github.com/tmux/tmux/wiki/Control-Mode) 的 `%output` 与八进制转义用于原始输出采集。Bash PS0/PROMPT_COMMAND 与 tmux 3.0a 的具体行为以本次真实设备原型结果核实；终端会话持久性沿用 V0.3 已验收实现。
