## 已定位与修复

- ssh2 1.17 附带示例仍使用旧的顶层 sftp 常量导出；当前实际位置为 utils.sftp。只修正测试 fixture 导入，没有修改依赖源码。
- 断线测试发现已关闭 SFTP 通道上的 close/unlink 请求可能不回调，使取消后的流清理等待不结束。对本软件独占 SFTP 实例的流句柄关闭增加所有权/通道状态判断；其他 SFTP 请求在已关闭状态立即报错。断线后不发布最终文件，同一软件会话重连时清理精确登记的本次临时文件。单项回归约 144ms 结束，随后 16/16 测试通过。
- 文件行选择最初重建整行会破坏双击事件目标，改为只更新选中状态；路径加载失败时恢复实际目录地址，避免显示地址与传输目标不一致。均为本次新增文件页内修改。
- T017 板端 Codex 因 workspace routing discovery timed out 失败，命令数 0、修改数 0；证据已回收。停止同通道模型重试，电脑通过直接 SFTP 有限脚本进行本次实机验证，不扩大板端权限或运行其他业务。

## 真实验证与界面检查

- 真实 SFTP 通过中文/空格/#/单引号路径、二进制和空文件/空目录、上传覆盖拒绝与 OpenSSH 原子覆盖、下载哈希、双向限速中取消、专用只读目录权限失败、上传中断线与重连后临时文件清理。目录和哈希在 v02-real-sftp.json，密码只通过 stdin 传入，没有写入脚本或日志。
- UI 脚本初次在 DOM 就绪前读取控件失败；增加就绪等待。每次 UI 重试使用不同的专用目标目录及下载目录，避免旧结果被误判为新一轮成功。
- 原生确认首轮以 UIA 索引点预期取消按钮，实际结果为覆盖完成，只改动测试副本。刷新真实窗口后改用 Esc，得到 canceled/0 个完成文件。不得把首轮当作取消通过，也未把控件操作问题误报为产品覆盖确认失效。
- 打包 EXE 的真实浏览器鼠标事件验证双击目录/上一级、新建远端目录、上传下载与哈希、原生取消确认；限速大文件出现进度后取消，目标无半文件，远程桌面保持 connected 并仍显示真实画面。
- Detector 因解析器缺失仅正则退化运行一次，[] 不代表完整 UI 验证。独立终检未发现功能/布局阻断，仅要求同步当前 V0.2 入口与设计文档，正在合并该项。

设计记录补写过程的首个脚本因旧组件缺少可选 refersTo 字段在写入前停止，改用 get 后完成；PyYAML 不在环境中，改用标准库校验已有映射结构，没有为文档验证安装新依赖。只更新 DESIGN.md 与设计 sidecar，没有更换视觉系统。
